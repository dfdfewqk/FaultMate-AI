## 독립 평가: 원본별 분할

**데이터 분할은 특징값을 보기 전 고정 시드(20261105)로 베어링 ID와 라벨만 사용하여 결정했습니다.** 일반적인 측정 파일 기준 임의 분할이나 모델 출력 선택을 하지 않았습니다.

- 최초 학습: `K001 K003 K004 K005 KA04 KA16 KB23 KI16` = **8 베어링**
- 개발 검증: `K002 KI04` = **2 베어링** (이후 10개 개발 자산으로 학습)
- 별도 최종 시험: `K006 KI18` = **2 베어링**, 실제 물리 베어링이 개발 학습에 전혀 포함되지 않음
- 10개 개발 베어링에 대해 각 베어링을 한 번씩 완전히 제외한 Leave-One-Bearing-Out 검사 실시. 로지스틱 회귀 C=1.0, 고정 분류 기준 0.5, 학습 자산별 동일 총 가중치.

| 평가 대상 | 독립 베어링 수 | 정확도 | Macro-F1 | 정상 오경보 | 손상 미탐 |
|---|---:|---:|---:|---:|---:|
| 개발자산 10개 LOBO 교차검증 | 10 | **60.0%** (6/10) | **58.33%** | **3건** | **1건** |
| 별도 물리 베어링 2개 최종 시험 | 2 | **100%** (2/2) | **100%** | 0건 | 0건 |

LOBO 혼동행렬, 행=실제 건강/손상, 열=예측 건강/손상:
```
              예측 정상   예측 손상
실제 정상        2          3
실제 손상        1          4
```

최종 2개 시험은 정상 K006/손상 KI18을 맞혔지만, **2/2 성공으로 일반적인 정확도가 100%라고 말할 수는 없습니다.** 더 중요한 10개 개발 자산 LOBO 결과의 정확도 60%, Macro-F1 58.33%, 정상 오경보 3건·손상 미탐 1건은 상용/현장 상태판정에 충분하다고 보기 어렵습니다.

다른 장비에서의 정상/손상 구분, 새로운 제조사 베어링, 다른 운전 조건이나 실제 설비 진단 수준의 정확도를 입증하지 못했습니다.

## 실제 구현 및 실험 산출물

- `scripts/extract_paderborn_unitless.py`: 원본 SHA·결합 원신호 지문 검증 및 무차원 특징 12개 추출. 모든 Windows matrix job 성공.
- `scripts/train_paderborn_unitless.py`: 12개 실제 새 특징 보고서와 Stage3의 실제 MAT 감사 JSON 12개를 결합하여 **956개 진짜 신호 자료로 모델 적합, 10개 개발 LOBO, 2개 새 베어링 시험 성공**.
- `tests/test_unitless_real_ml_pipeline.py`: 별도 합성/예외 소프트웨어 검사. 기존 앱 포함 Python 전체 257개 통과.
- GitHub Actions 아티팩트 `stage4-real-12-bearing-unitless-evaluation-unapproved`: 실제 평가 JSON과 **experimental_unapproved** 모델 계수. 공개 배포·자동 설치하지 않고 저장 기간 7일.
- 앱 기본 `faultmate/integration/ml.py`의 미승인 모델 차단과 P2 진단/DeepSeek 로직, 사용자 기존 기록 전부 보존.
- **정식 모델 `bearing_validated.json`/EXE/ZIP 미제작**, 실제 사용자 PC 테스트·유료 DeepSeek 실호출 없음.

## 다음 품질 개선 작업 (이 실험 결과를 재활용하여 시행)

1. **개발 베어링의 3개 오경보·1개 손상 미탐** 원인(운전조건·특징·클래스별 분리도)을 분석하고 10개 개발 베어링 안에서만 대안 모델/특징을 비교한다.
2. 기존 두 시험 베어링의 결과는 이미 한 번 확인했으므로 이후 개발에 재사용한 성능을 **새로운 봉인 시험 결과라고 재주장하지 않는다.** 진정한 독립 외부평가에는 별도 베어링과 현장 데이터가 필요하다.
3. 모델이 소규모 실험에 적합하다고 판단돼도 **연구/교육용 실험 모델과 현장 사용 승인 모델을 분리**하고 실제 단위 미확정/12개 베어링 한계를 화면에 명시한다.
4. 별도 출처 검토 또는 추가 독립 자산 평가를 통과하기 전에는 기본 ML API를 학습 완료·고장 확정 상태로 활성화하지 않는다.

이 결과는 *실측 ML 실험 수행 완료*이지, *최종 FaultMate AI에 현장용 모델 활성화 완료*가 아니다.
