# FaultMate AI — Antigravity 최소 작업 지시서 (P7.2 최종 통합본)

## 기준 소스 및 작업 원칙

- 기준 저장소: https://github.com/dfdfewqk/FaultMate-AI
- 기준 브랜치: `main`. **작업 시작 시 GitHub 최신 HEAD를 확인**하고 `main`의 P7.2 최종 소스를 바탕으로 별도 작업 브랜치를 만든다.
- P7.1 또는 P0~P6 ZIP을 기준으로 되돌리거나 MicroLoss AI/Smart Maintenance의 소스를 섞지 않는다.
- P7.2는 Windows 사용자 직접 실행에서 정상 작동한다고 보고됨(2026-10-30). 기존 기본 화면을 반복해서 재구축·재테스트하지 않는다. AI/ML 연결 후의 변경 부분만 추가 점검한다.
- 안전 확인, 증상 기반 7개 사례 추천, 진단 상세 보기, 자료실 지연 로딩, 결과 복사, 기존 API 계약을 유지한다.

## 이미 구현되어 있어 재구현하면 안 되는 부분

- 로컬 규칙 기반 고장 검토, 안전 차단 및 P7.2 UI.
- `POST /api/agent/review`: 동의 검증, 근거 미리보기, 서버 환경변수 `DEEPSEEK_API_KEY`, 외부 HTTPS 요청, 출력 인덱스 검증의 기본 구현.
- `POST /api/ml/inspect`: 베어링 특성 CSV 검증, 미승인 모델 차단.
- `scripts/train_ml.py`: 특성 CSV 기반 학습·평가 및 베어링 그룹별 분리. 실제 데이터로 학습한 모델은 아직 없음.
- 기존 자동 테스트. 변경된 기능의 테스트만 추가하고 회귀 테스트는 보존한다.

## 실제 남은 핵심 작업 (이 순서대로)

1. **공개 실측 데이터 변환:** Paderborn Bearing DataCenter의 원본 `.mat`를 가져와 측정 구조·물리 단위·라벨 출처를 검증한 다음 `docs/P6_AI_ML_IMPLEMENTATION.md`에서 정의한 특성 CSV로 변환한다. 원본 출처 및 CC BY-NC 4.0 이용 조건을 명시한다. 확인 불가능한 라벨/단위는 임의로 채우지 않는다.
2. **실데이터 ML 학습 및 독립 검증:** 기존 `scripts/train_ml.py`를 사용한다. 동일 베어링의 데이터가 train/test에 동시에 들어가지 않게 확인하고 오탐·미탐 및 홀드아웃 평가를 기록한다. 성능이 적절하지 않다면 모델을 활성화하지 않는다. 사용자에게 보고하기 전에 `validated`로 임의 전환하지 않는다.
3. **DeepSeek 실제 통신 검증:** API 키를 환경변수로만 넣고 실호출·429/500/timeout 등 실패 상황을 확인한다. 동의 전과 긴급 위험 상황의 외부 요청은 0회여야 한다. 실패해도 기존 로컬 진단은 작동해야 한다. 키를 코드·로그·커밋에 포함하지 않는다.
4. **AI/ML 통합 이후 변경분 최종 점검:** 새 연결 경로의 결과 표시·안전 차단·사용 동의와 기존 P7.2 회귀 테스트를 확인한다. 변경 파일, 실행한 테스트, 미검증 항목, 커밋 SHA를 보고한다.

## 금지 범위

- 신규 UI/백엔드/학습 파이프라인 전면 재개발, 불필요한 기능 추가, 기존 사용자 데이터 삭제.
- 기존 7개 설명용 사례를 실제 ML 학습 정답으로 사용하는 행위; 합성 샘플을 실측 성능으로 홍보하는 행위.
- 설비 직접 제어, PLC·Modbus 연결, 인터록 우회, 자동 재가동, 고장 원인 확정, 정비 작업 승인.
- API 키, 실설비 자료, 개인정보를 GitHub 또는 외부 AI에 무단 공개.
- 테스트를 수행하지 않았으면서 완료했다고 보고하는 행위.
