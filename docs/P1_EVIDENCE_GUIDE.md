# FaultMate AI P1 — 근거 사례집 사용·검증 기준

## 무엇을 구현했나
- 공식 기관의 위험 에너지 격리 안내와 제조사 기술 문서의 **사례 수준 원인 후보**를 분리해 기록.
- 컨베이어(3)·모터(2)·광전센서(2) 총 7개 설명용 사례, 출처 8개.
- 안전 조건, 미확인 상태, 관찰할 수 있는 기존 기록, 추가 질문, 원인 후보마다 근거 ID 및 적용 한계 기록.
- `GET /api/knowledge/overview`, `.../sources`, `.../cases`, `.../cases/{id}` 읽기 전용 API 및 근거 자료실 화면.

## 검증 수준
출처 문서의 내용 자체는 제조사/안전 기관의 공개 문서에서 확인한 것. 사례 조합·질문·후보 선정은 **FaultMate 프로젝트 제작자에 의한 설명용 정리**. 실제 설비 고장에 대한 진단 정답, 현장 검증, AI 학습용 라벨, 설비별 매뉴얼 일치 보증 아님.

제조사 매뉴얼은 **그 제조사 해당 시리즈**에만 정식 적용된다. 모델 미상 설비에 범용 공인 진단 절차처럼 적용하지 않는다. 알람 코드를 임의로 만들지 않는다.

## 안전 경계
- 기계 내부 접근, 끼임 구간 확인, 잼 해소, 전기 연결 측정, 커버 개방, 기계 조정은 각 사업장의 권한·설비별 에너지 차단/잠금·잔류 에너지 확인 절차에 따라야 한다.
- 사례 화면은 지시서가 아니라 확인할 **기존 기록과 안전 거리에서 가능한 관찰 항목**이다.
- 특정 모델의 상세 절차는 OEM 매뉴얼과 사업장 안전 관리자의 승인 없이는 제공하지 않는다.
- OSHA/HSE는 미국·영국의 참고 자료로서 한국 법적 준수 판단을 대신하지 않는다.

## 데이터 계약 및 인계
- P1 `catalog.json`에 `schema_version`, `sources`, `cases`, `safety_policy` 제공.
- 에이전트/ML 담당: **Antigravity**. P1 코드에는 DeepSeek API/학습/예측/자동 진단 포함하지 않음.
- 후속 에이전트는 `case_status`, `source_ids`, `limit`, `not_confirmed`, `required_safety_gate`를 그대로 보존해 인용 및 불확실성을 표시해야 함.
- 명시적 사용자 동의 없이 업체 데이터와 정비 기록을 외부 DeepSeek API로 보내지 말 것.
- 현장 자료 사용 시 제조사·모델·설비별 위험 에너지·문서 개정일·출처·권한을 검증하고 P1 예시를 별도 승인 기록으로 대체할 것.

## 제조사 문서·안전 자료
각 링크와 적용 한계는 `faultmate/knowledge/catalog.json`의 `sources` 항목에 저장됨. 원문 파일을 번들에 포함하거나 복제하지 않음.
