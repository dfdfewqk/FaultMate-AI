# FaultMate AI — Paderborn 원본 RAR 직접 분석(연구용) + 안전성·신뢰성 차단 검증 (2026-11-05)

## 이번에 해결한 사용 흐름

기존에는 `K001.rar` → CLI 실행 → 별도 특징 JSON 생성 → 앱 JSON 업로드 → 연구용 ML 점수의 여러 단계가 필요했다.

이제 고급 분석 화면의 **「Paderborn 베어링 실험용 ML · 미승인」 → 「원본 베어링 RAR」 → 「원본 RAR 자동 분석 · 연구용 ML」** 한 경로로 통합했다. 앱은 브라우저에서 해당 RAR을 **같은 PC의 `127.0.0.1` 로컬 서버**로 스트리밍하고, 그 요청에서 실제 원본 MD5 + 7-Zip 압축 무결성 + 4개 조건 × 각 20회 = 80개 MATLAB 진동·전류 신호를 확인한 뒤 원래 고정 모델의 12차원 특징·중앙값·점수 연산을 수행한다.

- 대상은 기존 원저자 자료 목록에 있는 **12개 Paderborn 베어링 원본 RAR**로 제한하며 소문자 등 이상한 이름은 인식하지 않는다. 파일 이름은 자산 ID를 찾는 용도일 뿐, **원본 진위는 파일 전체의 공식 MD5와 압축·MAT 검증으로만 확정**한다.
- 파일 크기 제한은 **최소 100,000,000 bytes ~ 최대 768 MiB**, HTTP 헤더와 실제 받은 바이트를 각각 제한한다.
- 브라우저와 서버가 원본 RAR을 영구 저장하지 않는다. 임시 폴더에 원본을 **부분별 기록**하고, 검사 직후 삭제한다. 80개 MAT의 원본 신호는 기존 일시 추출 방식으로 처리하여 업로드 응답이나 로그에 포함하지 않는다.
- 원본 파일 경로를 입력받아 로컬 파일 시스템을 임의로 읽는 기능은 없다. **일회성 업로드된 RAR 바이트만 처리**한다.
- 서로 다른 RAR 처리가 겹치면 **409**, 크기 초과는 **413**, 원본 불일치/채널 누락/잘못된 파일은 **예측 없이 거절**, 저장 공간 부족은 **507**. 7-Zip 없는 경우에도 가짜 결과를 만들지 않는다.
- 긴급 위험 선택 시 브라우저의 **이전 ML 결과를 즉시 지우고 요청 표시를 취소**한다. 이미 원본 검사 스레드가 시작됐다면 안전한 읽기 전용 작업은 종료까지 이어질 수 있다. 이 처리는 **설비 동작, 재가동, 원격 제어를 절대 하지 않으며**, 종료 후 임시 원본과 동시 실행 잠금을 해제한다.
- DeepSeek 실서버로 RAR/특징/장비 기록을 **절대로 보내지 않는다**. 사용자 개인정보/API 키/원본 경로도 응답에 노출하지 않는다.
- 기존 특징 JSON 방식은 **고급 항목**으로 남겨 두었다. 이 방식은 JSON 자체가 원본 신호의 암호학적 증거가 아니라는 경고를 유지한다. 기존 3개 SI 입력 CSV 정식 ML은 계속 미승인·비활성 상태다.

## ML 신뢰성은 다음과 같이 구분

| 항목 | 검증 의미 |
|---|---|
| 실제 원본 RAR 공식 MD5·4조건×20회 진동/전류 기록 | **입력 무결성** 검증 |
| 실측 특징 12개 추출 → 기존 모델 점수 | **연구 추론 연결** 검증 |
| CLI·특징 JSON API·이번 원본 RAR 직접 API 결과 동일 | **계산 재현성** 검증 |
| 새 독립 정상 물리 베어링의 오경보율·특이도 | **아직 없음** |
| 현장 센서 신호 계약과 3특징 SI 입력 일치 | **아직 아님** |
| 현장 설비 고장 확정·정비 허가 | **금지** |

K001은 실제 이미 학습에 사용된 정상 베어링이므로 해당 원본이 정상으로 분류되더라도 **새로운 정상 독립 검증, 정확도, 오경보율로 보고하지 않는다**. 앞서 개별 새로운 손상 베어링 8개에서 7개를 검출하고 KI21은 놓친 기록도 그대로 유지한다. 이 모델의 학습 데이터는 **CC BY-NC 4.0**, 운영·상업적 활용에는 별도 이용 조건 검토가 필요하다.

## 코드·테스트

- `faultmate/integration/research_raw_archive.py`: 본문 제한, 비동기 스트리밍, 임시 파일, 디스크 여유·동시 실행 잠금, `asyncio.to_thread`를 통한 기존 RAR 추출과 고정 모델의 정확한 재사용, no-model-activation 플래그. 클라이언트 중단 후에도 읽기 전용 스레드가 사용 중인 임시 RAR을 조기 삭제하지 않는다.
- `faultmate/app.py`: 기존 로컬 Host/Origin 보호 아래 **별도** `POST /api/ml/experimental-original-rar` 경로. 원본 신호·사용자 경로를 반환하지 않는다.
- `web/index.html`, `web/app.js`: "원본 RAR 자동 분석" 입력을 1순위로 추가, 기존 JSON은 접기; MD5/80MAT/실험점수만 표시, 위험 징후 발생 시 화면 결과 제거.
- `tests/test_research_original_rar_upload.py`: **합성 데이터**로만 크기·청크 스트리밍·원본 베어링 명단·외부 Origin/Host·동시 실행·디스크 부족·가짜 MD5·임시 폴더 제거·미승인 모델 상태를 검사한다. 이 테스트의 결과는 실제 데이터 성능을 뜻하지 않는다.
- `tests/windows_native_browser_acceptance.py`: 실제 Windows 배치파일→로컬 Uvicorn→Chromium에서 새 원본 파일 선택과 크기 오류·위험 차단을 검증하고 기존 특징 JSON 모드 회귀를 유지한다.
- `scripts/check_real_rar_direct_local_api.py`: 기존 GitHub Windows runner의 **원저자 K001 RAR 실제 다운로드 및 원본 MD5와 전체 80개 MAT 검증 이후**, 원본 RAR을 새 로컬 API에 직접 스트리밍해 **두 번째 독립 실행 경로의 고정 모델 점수가 기존 CLI 결과와 완전히 같은지 확인**. 원본 자체를 GitHub 배포 아티팩트로 공개하지 않는다.
- `.github/workflows/stage7-direct-original-rar-ml.yml`: Linux+Windows Python, 기존 실제 Windows 브라우저/Chromium 회귀, 실제 K001 원본 실험 모델 점수·직접 API 점수까지 연속 검증한다.
