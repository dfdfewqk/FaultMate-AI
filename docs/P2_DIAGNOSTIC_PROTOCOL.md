# P2 설비 고장 후보 검토 프로토콜

## 입력 / 전제
- 사용자에게 사례를 선택하도록 요구. 자유 입력 문장은 참고용으로만 저장하지 않고 응답으로 돌려주며 고장 원인 자동 결정에 사용하지 않음.
- 사용자가 직접 선택한 사례의 P1 `candidate_causes`만 제공.
- 관찰 값은 기존 HMI/PLC 기록 및 안전한 거리의 외부 관찰. 측정·조작을 지시하지 않음.
- 관찰은 실제 검증 데이터와 분리된 사용자 자가 보고. `yes`만 해당 원인을 **확인할 순서**에 반영. `no`가 원인 배제/확정의 증거가 되지 않음.
- 자유 입력 알람 코드로 임의의 제조사 알람 해석 금지.

## API 응답
- `selection_required`: 사례 미선택. 자유 입력에서 발견한 키워드 기반 참고 목록만 반환; 원인 후보 없음.
- `candidate_review`: 선택 사례의 미확정 후보 및 출처·미답변 관찰 질문·일반 증거 확인 질문·안전 조건.
- `safety_hold`: 위험 징후를 `yes`로 보고한 경우 안전 우선. 원인 후보 반환 중단.
- HTTP 422: 스키마 오류, 지원하지 않는 설비·관찰 ID, 해당 사례에 맞지 않는 관찰, 양식 오입력.
- HTTP 404: 등록되지 않은 사례 ID.
- 모든 상태의 `confirmed_fault=false`, `safe_to_work=false`, `external_transfer=false`, `stored=false`.

## 유의 사항
- `review_group`은 확률이 아니라 단순 관찰 여부에 따른 교육용 검토 순서.
- 특정 설비 모델의 출처 적용 가능성은 확인되지 않음. OEM 원문과 국내 현장 절차를 따름.
- DeepSeek는 P3 Antigravity에서 별도 연동하며 P2의 불확실성 플래그를 변경하지 못함.
- ML은 모델별 정답 데이터 확보/검증 전에는 예측 확률 표시 금지.
