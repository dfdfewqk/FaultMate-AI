# FaultMate AI — P7.2 5단계: 결과 요약 복사·기술 정보 정리

컨베이어·모터·센서의 **고장 원인 후보와 추가 확인 질문**을 정리하는 교육·포트폴리오용 로컬 앱입니다. 자동 고장 확정, 설비 제어, 인터록 우회, 작업 허가 기능이 없습니다.

## 현재 구현

- P1: 고장 검토 사례 7개, 출처 8개. **설비별 모델·실고장 정답이라고 주장하지 않습니다.**
- P2: 기존 7개 사례를 증상 키워드로 추천하고 작업자가 최종 사례를 선택. 관찰 예/아니오/모름, 후보·추가 확인·안전 조건. 긴급 위험에서 후보 비공개 및 추가 요청 차단.
- P5: 화면 전환·가상 사례 입력·최신 응답 유지·안전한 HTTPS 근거 링크·기존 입력 무저장.
- 실사용 화면 간소화: 첫 화면에서는 고장 진단만 노출, 선택 입력·근거 자료·AI/ML 기능은 펼쳐 볼 수 있도록 정리, 개발 단계 홍보·중복 시나리오 패널 제거. 기존 기능이나 API는 삭제하지 않았습니다.
- P6 Agent: AI 전송 예정 근거 미리보기, **매번 동의**, 로컬 사전검증, DeepSeek 요청 구성. 모델은 기존 근거 순서 인덱스만 답할 수 있으며 다른 지시는 무시합니다. 외부 전송을 선택하지 않으면 로컬 진단만 작동. **실제 키 기반 API 성공은 아직 미검증.**
- P6 ML: 실제 진동/전류 **특성 CSV** 입력 검증, 베어링 그룹 단위 학습·평가 스크립트, 승인된 모델만 추론하는 API. **실제 데이터 변환·학습·검증 모델은 없음.** 그러므로 기본 상태는 `unavailable`이고 예측을 내지 않습니다.

## Windows 실행

1. ZIP 해제 후 `FaultMate-AI/start_windows.bat` 더블클릭 (Python 3.10 이상 권장, 최초 종속성 설치 필요).
2. 열린 브라우저 또는 `http://127.0.0.1:8787/`에서 `예시 입력 불러오기` → `원인 후보 · 질문 검토` 실행.
3. 실제 진단 시 설비 종류와 관찰한 증상을 입력 → 관련 사례 추천 확인 → 검토할 사례를 직접 선택. 맞는 사례가 없으면 지원 범위 밖으로 판단하고 무리하게 선택하지 마세요. 입력은 저장하지 않습니다.
4. AI 기능은 선택 사항. `DEEPSEEK_API_KEY`를 **서버 환경변수로만** 지정할 수 있으며 API 요금이 발생할 수 있습니다. 소스나 HTML에 키를 넣지 마세요. 사용 전 **전송 예정 자료 확인 → 요청별 동의 → 실행**. 가상 고장 사례는 AI 전송이 차단됩니다.
5. 결과가 정상적으로 생성되면 `진단 요약 복사`를 눌러 작업자용 텍스트로 복사할 수 있습니다. 클립보드 복사는 저장이나 외부 전송이 아니며 공유 전에 관찰 내용과 안전 주의를 확인하세요. 모델명·알람 원문은 복사에 포함하지 않습니다.
6. ML은 검증 모델이 없으면 예측을 내지 않습니다. 학습 자료와 실행 조건은 `docs/P6_AI_ML_IMPLEMENTATION.md`를 참조하세요.

P6 버전의 Windows 실행 영상은 확인했으나 P7.2 5단계 수정본의 Windows 실기기 더블클릭 검증은 아직 진행하지 못했습니다. 외부 API 사용 여부와 센서 정확도를 현장 데이터 없이 확인했다고 주장하지 않습니다.

## API

- 기존: `GET /api/status`, `/api/scope`, `/api/knowledge/*`, `/api/diagnostics/options`, `POST /api/diagnostics/evaluate`, `GET /api/integration/capabilities`, `POST /api/integration/evidence-preview`
- 추가: `POST /api/agent/review` (`{"triage":{...},"consent":true}`), `POST /api/ml/inspect` (`Content-Type:text/csv`와 CSV 바이트 본문, 최대 256KB)
- 모든 결과는 고장 확정 `false`와 작업 허가 `false`. AI 사용 여부·실제 연결 여부 별도 표기.

## 테스트

```bash
python -m pip install -r requirements.txt pytest httpx
python -m pytest -q tests
node --check web/app.js
# Chromium + playwright가 준비된 QA 환경만:
PYTHONPATH=. python tests/browser_smoke.py
```

ML 학습(실제 물리 단위·출처·라벨 검증된 CSV를 확보한 경우에만):

```bash
pip install -r requirements-ml.txt
python scripts/train_ml.py real_bearing_features.csv --output models/evaluation
```

학습 결과는 기본적으로 **배포 불가인 평가용(`evaluated_pending_review`)**입니다. 실제 정답 데이터가 없으면 수행하지 마세요. Paderborn 원데이터는 **CC BY-NC 4.0**, 상업적 사용은 별도 허가 필요.

Antigravity 최소 지시서는 `docs/ANTIGRAVITY_IMPLEMENTATION_ORDER.md`이며 기존 MicroLoss AI와 Smart Maintenance 원본은 변경하지 않았습니다.

## P7.1 디버깅 기록 (2026-10-30)

- CSV 길이 제한 내에서 Python CSV 파서 제한을 초과한 헤더·필드는 기존 500 예외 대신 `unsupported_input`으로 처리.
- AI 미리보기를 다시 열면 이전 미리보기·동의 내용 초기화.
- ML CSV 파일 변경·긴급 위험 발생 시 이전 요청을 취소하고 오래된 결과를 폐기.
- 잘못된 URL 해시로 화면 초기화가 중단되지 않도록 보호.
- 상태 API에 `ui_release=P7.1`을 추가하고 ML 상태 오표시(`not_included`)를 `unvalidated`로 수정. 과거 `phase=P2`는 규칙 기반 진단 엔진 호환 표기로 유지.
- 실제 DeepSeek 통신과 ML 공개 데이터 실학습은 이번 디버깅 범위가 아님.

## P7.2 1단계: 증상 기반 사례 추천 (2026-10-30)

- 기존 백엔드 `suggestions()` 및 `POST /api/diagnostics/evaluate`의 `selection_required` 응답을 **화면에서 재사용**. 별도 AI/ML/신규 엔드포인트 추가 없음.
- 설비 종류와 증상을 먼저 입력하면 350ms 지연 후 로컬 요청으로 교육용 사례 목록을 표시. 추천 결과는 **진단이 아니며 자동 선택하지 않음**.
- 작업자가 추천 사례를 클릭하거나 기존 목록에서 직접 사례를 선택해야 진단 버튼을 사용할 수 있음.
- 증상/설비 변경 시 앞선 사례 선택과 진단 결과를 무효화. 긴급 위험 시 모든 추천 요청 취소·화면 차단.
- 키워드 일치가 없으면 지원 범위 밖일 수 있다고 표시. 부정어·전후 맥락·설비 적합성은 자동 분석하지 않음.
- 모델명·알람 원문은 아직 추천/원인 우선순위에 사용되지 않으며 고급 추가 입력으로 유지.
- Python 테스트·브라우저·HTTP 회귀 및 새로운 사례 추천 브라우저 테스트를 유지해야 함.
- 2단계 안전 상태 안내, 3단계 결과 요약, 4단계 자료실 지연 로딩을 현재 통합본에 모두 반영했습니다.


## P7.2 2단계 — 안전 상태 안내 명확화 (2026-10-30)

- 진단 양식 상단에서 긴급 위험 여부를 먼저 확인하고 '있음/미확인/관찰된 위험 없음'의 의미를 구분합니다.
- '미확인' 상태에서는 정보 검토를 허용하되 안전 확인이나 실제 정비 승인으로 오해하지 않도록 표시합니다.
- '관찰된 위험 없음'은 안전 확인 완료를 뜻하지 않으며 사업장 작업 승인 및 에너지 차단·잠금·잔류 에너지 확인 절차가 별도로 필요합니다.
- '긴급 위험 있음'을 선택하면 진단, 추천, 예시 입력, AI 실행/미리보기, ML 업로드/실행을 차단합니다.
- 확인 상태를 변경하거나 초기화할 때 이전 진단 결과를 무효화합니다. 기존 진단 API, 추천 기능, 근거 출처, AI·ML 연결 계약은 유지합니다.
- Windows 실제 실행은 별도 확인이 필요합니다.

## P7.2 3단계 — 진단 결과 간소화

원인 후보, 먼저 확인할 기존 기록, 안전 주의를 우선 표시합니다. 출처·적용 한계·전체 질문은 결과 상세 보기로 이동했으며 정보는 삭제하지 않았습니다. `docs/P7_2_STAGE3_REPORT.md`를 참고하세요.

## P7.2 4단계 — 자료실 지연 로딩 및 반응성 개선

- `web/app.js`: 앱 최초 실행 시 상태 API와 고급 AI/ML 연결 상태 요청을 비동기로 수행하여 핵심 진단 입력 준비를 차단하지 않습니다.
- 근거 자료실은 사용자가 펼칠 때에만 출처 및 사례를 요청합니다. 접힌 상태에서는 별도 자료 API 요청이 없습니다.
- 자료실 첫 조회가 실패해도 진단은 유지하고, 자료실을 다시 열어 실패 요청을 재시도합니다.
- 반복 열고 닫기는 이미 가져온 데이터를 재사용하며, 필터 변경과 늦은 응답의 경쟁 상태를 방지합니다.
- `tests/browser_step4.py`: 느린 서버 상태·고급 상태·자료실 응답, 자료실 출처 오류, 재시도, 필터 선택, 재열기와 초기 진단 비차단을 자동 검증합니다.
- 실제 Windows 실행, DeepSeek 외부 통신, 실측 ML 모델 학습은 진행하지 않았습니다.


## P7.2 5단계 — 현장 결과 전달 간소화 (2026-10-30)

- 성공적으로 완료한 로컬 원인 후보 검토에만 `진단 요약 복사` 버튼을 표시합니다.
- 설비 종류, 작업자 입력 증상, 원인 미확정 후보 전체, 우선 확인할 기존 기록 2개, 안전 조건과 중단·보고 기준을 텍스트로 복사합니다. 가상 입력은 가상 사례임을 명시합니다.
- 입력 변경·긴급 위험 선택·초기화 시 기존 버튼을 제거합니다. 브라우저에서 클립보드 권한이 없으면 오류 문구를 표시합니다. 복사는 로컬 브라우저 조작이며 자동 파일 저장·외부 API 호출이 없습니다.
- 초기 화면 상단에서 중복 AI 연결 표기를 없애고 `고급 분석` 접힌 영역 안에서만 연결 정보를 확인할 수 있게 옮겼습니다. AI·ML 기능은 삭제하지 않았습니다.
- Python/Chromium/HTTP 자동 검사를 실행했으며 Windows 실기기와 실제 DeepSeek·ML 학습 완료는 주장하지 않습니다.
- 6단계는 통합 디버깅 및 Windows 1회 검증으로 제한합니다. 새 기능을 추가하지 않습니다.
